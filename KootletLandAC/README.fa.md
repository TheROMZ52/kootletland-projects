# KootletLandAC — ضدتقلب مبتنی بر شواهد

[English](README.md) · [فارسی](README.fa.md)

KootletLandAC یک افزونهٔ ضدتقلب برای Paper 1.21.x است که برای شبکهٔ کتلت‌لند ساخته شده است.

این افزونه بر اساس یک آستانهٔ منفرد بازیکن را مجازات نمی‌کند. هر تشخیص به‌صورت یک **شاهد همراه با میزان اطمینان** ثبت می‌شود؛ شواهد در طول زمان جمع‌آوری و بین بررسی‌های مختلف مقایسه می‌شوند و سپس می‌توانند به هشدار تبدیل شوند.


> وضعیت نسخهٔ 1.2.0: پروژه در CI کامپایل می‌شود و تست‌های واحد را می‌گذراند، اما هنوز با بازیکنان واقعی روی سرور زنده اعتبارسنجی نشده است. هشدارها را سرنخ بررسی تیم مدیریت در نظر بگیر، نه اثبات قطعی تقلب.

## نصب

1. پیش‌نیازها: Paper 1.21.x و Java 21. افزونه‌های GrimAC، LiteBans و LuckPerms اختیاری‌اند.
2. با `gradle build` خروجی بساز یا Artifact مربوط به CI را دریافت کن.
3. فایل `build/libs/KootletLandAC-*.jar` را داخل پوشهٔ `plugins/` قرار بده.
4. سرور را یک بار اجرا کن و سپس `plugins/KootletLandAC/config.yml` را ویرایش کن.
5. دسترسی‌های `kootletlandac.alerts` برای دریافت هشدار و `kootletlandac.admin` برای فرمان‌ها را به اعضای تیم بده.

## تنظیمات مهم

| گزینه | کاربرد |
|---|---|
| `settings.alerts` | ارسال هشدار به اعضای دارای دسترسی `kootletlandac.alerts` |
| `settings.confidence-warning-threshold` / `violation-warning-threshold` | تعیین آستانهٔ هشدار MEDIUM |
| `settings.auto-punishment` | کلید اصلی مجازات خودکار؛ به‌صورت پیش‌فرض `false` |
| `bypass.mode` | حالت `skip` یا `log-only` برای بازیکنان معاف |
| `decision.high-alert-cooldown-ms` | فاصلهٔ کمتر بین هشدارهای سطح HIGH |
| `decision.very-high.commands` | فرمان‌های کنسول برای سطح VERY_HIGH؛ فقط با فعال بودن مجازات خودکار اجرا می‌شوند |
| `checks.movement.*` و `checks.combat.*` | فعال یا غیرفعال کردن بررسی‌ها |
| `integrations.grim` و `integrations.grim-confidence` | سیگنال اختیاری Grim |

فرمان `/kac reload` تنظیمات را دوباره می‌خواند؛ وضعیت بازیکنان را پاک یا Listenerها و Taskها را تکراری نمی‌کند.

## مسیر تشخیص تا تصمیم

```text
رویدادهای Paper
  → نرمال‌سازی رویداد و دادهٔ حرکتی
  → مدل وضعیت، فیزیک، پیش‌بینی و جبران تأخیر
  → بررسی‌ها و تولید Evidence
  → بافر و Violation Level
  → همبستگی بین بررسی‌ها و تحلیل رفتار در پنجره‌های زمانی
  → تصمیم: LOW / MEDIUM / HIGH / VERY_HIGH
```

- **پیش‌بینی حرکت:** مدل گرانش و حرکت عمودی، رفتار مورد انتظار را دنبال می‌کند. یک تیک غیرعادی به‌تنهایی کافی نیست؛ Fly و Speed به بررسی چند تیک متوالی نیاز دارند.
- **جبران لگ:** سابقهٔ Ping، نوسان تأخیر، TPS و MSPT در محاسبهٔ تلورانس‌ها دخیل‌اند.
- **زمینهٔ بازی:** Elytra، Riptide، Levitation، Jump Boost، یخ، Slime، Honey، آب و مایعات، Vine، Cobweb، Teleport، Knockback و Vehicle در بررسی حرکت لحاظ می‌شوند.
- **تصمیم چندسیگنالی:** سطوح بالاتر به اطمینان بیشتر و چند بررسی مستقل نیاز دارند. یک بررسی منفرد به‌تنهایی نباید به سطح VERY_HIGH برسد.

## بررسی‌ها

| بررسی | سیگنال‌ها |
|---|---|
| Speed | مقایسهٔ سرعت افقی مورد انتظار و واقعی با توجه به افکت‌ها و سطح زمین |
| Fly | انحراف از مدل گرانش و حرکت عمودی غیرممکن |
| NoFall | ادعای ایستادن روی زمین در حالی که سرور زیر بازیکن زمین نمی‌بیند |
| Jesus | ایستادن روی سطح مایع برای چندین تیک |
| Step، HighJump، LongJump | اختلاف جابه‌جایی عمودی و افقی با مدل پیش‌بینی |
| Timer | تعادل تعداد Packetهای حرکتی در زمان؛ با محافظت در برابر جهش لگ |
| Phase | برخورد واقعی Hitbox بازیکن با بلوک‌ها |
| NoWeb، Strafe، Motion، InvalidMovement | بررسی وضعیت‌های خاص و مختصات نامعتبر |
| Velocity | واکنش بازیکن به Knockback واقعاً اعمال‌شده |
| Reach | فاصلهٔ هندسی تا Hitbox با احتساب جبران تأخیر و خط دید |
| KillAura | ترکیبی از چرخش، زاویهٔ ضربه، تعویض هدف و زمان‌بندی |
| Aim | شکل تغییر زاویه و الگوی حساسیت؛ فقط سیگنال کمکی |
| AutoClicker | توزیع فاصلهٔ کلیک‌ها، Burst و آنتروپی |

فقط ضربه‌های واقعی از نوع `ENTITY_ATTACK` وارد بررسی‌های مبارزه می‌شوند؛ بنابراین آسیب Thorns یا Sweep نمی‌تواند به‌اشتباه شاهد مبارزه تولید کند.

## فرمان‌ها

| فرمان | توضیح |
|---|---|
| `/kac debug <player>` | نمایش وضعیت حرکت، پیش‌بینی، لگ، مبارزه، VL، اطمینان و شواهد اخیر |
| `/kac verbose <player>` | نمایش Debug همراه با دادهٔ خام آخرین شاهد |
| `/kac stats` | آمار بررسی‌ها، تشخیص‌ها، هشدارها، زمان اجرا و مصرف حافظه |
| `/kac checks`، `/kac integrations` | نمایش بررسی‌های فعال و وضعیت اتصال‌ها |
| `/kac alerts`، `/kac reload` | وضعیت هشدار/مجازات و بارگذاری دوبارهٔ تنظیمات |
| `/kac history <player>` | خواندن آخرین شواهد ذخیره‌شده در صورت فعال بودن Storage |
| `/kac profile` | نمایش زمان مصرف‌شده در بخش‌های مختلف |
| `/kac profile reset` | پاک کردن آمار Profiler |

## دسترسی‌ها

| Permission | پیش‌فرض | توضیح |
|---|---|---|
| `kootletlandac.admin` | op | دسترسی مدیریتی و فرمان‌ها |
| `kootletlandac.alerts` | op | دریافت هشدار |
| `kootletlandac.bypass` | false | معاف شدن از بررسی‌ها |
| `kootletlandac.alerts.network` | — | دریافت هشدار شبکه از سرورهای دیگر |

## اتصال‌های اختیاری

### GrimAC

اگر GrimAC نصب باشد، Flagهای آن از طریق Event Bus دریافت و به‌عنوان یک شاهد با نام `Grim` ثبت می‌شوند. Grim فقط یک سیگنال است، نه حقیقت قطعی؛ به‌تنهایی اجازهٔ هشدار یا مجازات ایجاد نمی‌کند.

اتصال Grim با Reflection ساخته شده و روی سرور زندهٔ Grim هنوز تأیید نشده است. در صورت ناسازگاری، افزونه اتصال را غیرفعال می‌کند و دلیل آن را در لاگ می‌نویسد.

### LiteBans و LuckPerms

فرمان‌های بخش `decision.very-high.commands` به‌صورت فرمان کنسول اجرا می‌شوند. بنابراین می‌توان از فرمان‌های LiteBans برای ثبت مجازات استفاده کرد. LuckPerms نیز دسترسی‌های `kootletlandac.*` را مانند سایر Permissionها مدیریت می‌کند.

### SQLite و MySQL

ذخیره‌سازی اختیاری است و نوع آن می‌تواند `none`، `sqlite` یا `mysql` باشد. شواهد از طریق صف محدود و یک Worker جداگانه به‌صورت دسته‌ای نوشته می‌شوند تا Thread اصلی سرور منتظر دیتابیس نماند. در صورت پر شدن صف، داده حذف و شمارش می‌شود؛ عملیات سرور مسدود نمی‌شود.

### Velocity

هر Backend تشخیص و تصمیم‌گیری را مستقل انجام می‌دهد. با فعال بودن `network.enabled`، شواهد مطابق حداقل اطمینان تنظیم‌شده از کانال `kootletlandac:evidence` ارسال می‌شوند.

ماژول `velocity/` هشدار را برای اعضای تیمی که روی سرور دیگری هستند نمایش می‌دهد. این ماژول فقط هشدارها را تجمیع می‌کند و مجازات مرکزی انجام نمی‌دهد.

## ساخت و توسعه

```bash
cd KootletLandAC
gradle test build
```

تست‌های واحد منطق‌های مستقل مانند آمار، جبران لگ، هندسهٔ Reach، تصمیم‌گیری، همبستگی، اعتبارسنجی Packet، ذخیره‌سازی SQLite و Profiler را پوشش می‌دهند.

تست یکپارچه با Paper زنده، Grim، LiteBans، LuckPerms و Velocity انجام نشده و برای آن‌ها به سرور واقعی نیاز است.

## محدودیت‌های شناخته‌شده

- لایهٔ Packet خام وجود ندارد؛ بررسی‌ها بر اساس رویدادهای Bukkit انجام می‌شوند.
- اندازه‌گیری Transaction و Keep-Alive پیاده‌سازی نشده است.
- ماژول Velocity فقط هشدارها را منتقل می‌کند؛ مجازات مرکزی وجود ندارد.
- حرکت ناشی از بعضی Pluginها، مانند Piston، ممکن است غیرعادی تشخیص داده شود.
- تشخیص Aim در Zoom Modها و ورودی لمسی Bedrock قابل اتکا نیست و فقط سیگنال کمکی محسوب می‌شود.
- شناور ماندن بدون ارسال Packet حرکتی قابل مشاهده نیست.
- کیفیت تشخیص روی سرور زنده هنوز اعتبارسنجی نشده است.

## تغییرات نسخهٔ 1.2.0

ذخیره‌سازی شواهد در SQLite/MySQL با نوشتن غیرهم‌زمان و نگهداری محدود، فرمان `/kac history`، پل پیام‌رسانی و ماژول Velocity برای هشدار بین سرورها، Profiler داخلی و تست‌های سناریویی به پروژه اضافه شدند.
